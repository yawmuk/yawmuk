# العرض النهائي «يومك» — طريقة التعبئة والتصدير

العرض مبني على القالب الرسمي للتحدي (`project_template.pptx`)، في 12 شريحة لعرض مدته 5 دقائق، والنص المقروء في [SPEAKER_NOTES.md](SPEAKER_NOTES.md) وداخل ملاحظات كل شريحة.

| الملف | الوظيفة |
|---|---|
| `build.py` | يبني `yawmuk-deck.template.pptx` من القالب، ويُبقي الرموز `{{…}}`، ويكتب `slots.json` و`SPEAKER_NOTES.md`. |
| `values.json` | القيم التي تملؤها أنت: الروابط ونتائج القياس ولقطات الشاشة البديلة. |
| `fill.mjs` | يستبدل الرموز ويضع اللقطات، ثم يصدّر `submission/Yawmuk_Final_Deck.pptx` و`.pdf`. |
| `img/` | اللقطات الحالية: المسجد، والمصحف، ولوحة الخبراء، والمواقيت. |
| `fonts/` | خط Readex Pro (بترخيص OFL) الذي يستخدمه القالب، وبه يخرج ملف PDF صحيحاً. |

## قبل التسليم (5 دقائق)

1. املأ `values.json`، واترك فارغاً كل ما لم يُقَس. الحقل الفارغ يظهر «—» في المؤشرات و«قيد القياس» في النصوص، **ولا يظهر رقم مخترع أبداً**.
   - `LIVE_URL` و`VIDEO_URL`: يبقى الرمز ظاهراً كما هو حتى تملأه، فلا يمرّ رابط ناقص دون أن تلاحظه.
   - `EVAL_PASS`: عدد الحالات الناجحة من الحالات الاثنتي عشرة، رقم واحد مثل `11`. و`EVAL_COMPARISON`: جملة قصيرة تقارن «يومك» بروبوت المحادثة العام على الحالات نفسها، مثل «يومك X/12 مقابل Y/12».
   - `STUDY_N` و`STUDY_GAIN` و`STUDY_RESULTS`: من `/results.html` كما تظهر هناك. إذا قلّ العدد عن 5 مشاركين في كل ذراع، فاكتب ما تقوله الصفحة: «بيانات غير كافية» مع الأعداد الخام.
   - `COST_MEASURED`: التكلفة الفعلية من فوترة Anthropic وCloud Run إن توفرت، وإلا فاتركه فارغاً.
2. (اختياري) لاستبدال لقطة، ضع مسارها نسبةً إلى `project/yawmuk` في `screenshots`، مثل `"SCREENSHOT_TOWN": "docs/deck/img/town-final.png"`، وسيقصّها السكربت على مقاس إطارها. اللقطات أربع:
   - `SCREENSHOT_TOWN` في شريحة الحل.
   - `SCREENSHOT_QURAN` و`SCREENSHOT_DASHBOARD` و`SCREENSHOT_PRAYER` في شريحة اللقطات.
3. شغّل:

```bash
cd project/yawmuk
node docs/deck/fill.mjs --auto     # --auto يشغّل npm test ويقرأ docs/SOURCES.md ويضع تاريخ اليوم
```

   يطبع السكربت الرموز التي بقيت دون قيمة. افتح بعدها `submission/Yawmuk_Final_Deck.pdf` وراجعه.
4. **راجع شريحة «ما أُنجز وما يأتي»** (11) وشريحة الحل (3): كل ميزة موصوفة فيهما بأنها «أُنجزت» يجب أن تعمل في الرابط الحي. إذا لم تكتمل ميزة، فاحذفها من النص في `build.py` ثم أعد البناء.

## إعادة البناء من القالب (بعد تعديل النصوص)

```bash
pip install python-pptx            # مرة واحدة
python3 docs/deck/build.py         # يقرأ ../../../../project_template.pptx افتراضياً
node docs/deck/fill.mjs --auto
```

## المتطلبات

- Node 22. و`unzip` و`zip` و`sips` موجودة في macOS.
- LibreOffice لتصدير PDF، ويُستخدم من `/Applications/LibreOffice.app` تلقائياً. السكربت يمرّر خط `fonts/` إلى LibreOffice عبر `FONTCONFIG_FILE`. إذا لم يكن LibreOffice مثبتاً، فافتح ملف PPTX في PowerPoint أو Keynote وصدّره PDF، بعد تثبيت خطوط `fonts/`.

## مبادئ المحتوى

- لا يحتوي العرض أي رقم غير مقيس: كل نتيجة إما محسوبة آلياً (`--auto`)، وإما تملؤها من مصدر مسمّى، وإما تبقى «قيد القياس».
- التكلفة 45 دولاراً لكل ألف لاعب موسومة صراحةً بأنها **تقدير** من [docs/AI.md](../AI.md)، أي 1 خطة و3 أسئلة لكل لاعب. أما القياس الفعلي فمكانه `COST_MEASURED`.
- الأحكام مسودات أعدّها الذكاء الاصطناعي وتنتظر مراجعة عالم، والعرض لا يدّعي أن عالماً راجعها. وتصف شريحة الموثوقية لوحة الخبراء بأنها آلية المراجعة.
- شريحة الموثوقية تسمّي المصادر المعتمدة **المستخدمة فعلاً**: نص مجمع الملك فهد عبر quranenc.com وapi.quran.com، وdorar.net، والشاملة. وكل مرجع من خارج الحزمة موسوم للمراجعة. إذا أُضيف استخدام فعلي لـ«بيّنات» (dawa.center) أو «الجمهرة» (islamic-content.com)، فأضفه إلى سطر المصادر في `build.py`.
